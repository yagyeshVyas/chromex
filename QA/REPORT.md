# CHROMEX — QA & Release Audit

**Date:** 2026-11-11
**Commit under test:** `43088437110` CI run (main)
**Verdict:** the **import and analysis paths are verified**; **runtime/browser behaviour is not**.
Sideload release is conditionally ready. App Store release is **not** ready.

This report separates what was executed from what was only inspected. No claim below is based on
"it should work".

| Item | Value |

  execution) **cannot be executed here**. It requires a signed app on a device.

  containment, compatibility analysis, filter rules — **is executed**, on both Linux and the iOS
  simulator.
- Performance is measured for the pure core (real numbers, §6). UI/browser metrics are **not**
  measured and are listed as such.

## 6. Performance measurements

Measured on this WSL host, Swift 6.4.2, release optimisation, pure core:

| Operation | Iterations | Total | Per operation |
|---|---:|---:|---:|
| `URLResolver.destination` | 20,000 | 193.4 ms | **0.0097 ms** |
| `ManifestParser.parse` | 2,000 | 13.2 ms | **0.0066 ms** |
| `CompatibilityAnalyzer.analyze` | 2,000 | 23.3 ms | **0.0116 ms** |
| `AdBlockRules.parse` (built-in list) | 200 | 148.8 ms | **0.744 ms** |

Interpretation: import analysis costs well under a millisecond per package; filter-list parsing
is sub-millisecond but should still happen off the main actor (it already runs during
`AdBlocker.prepare`).

**Not measured:** startup, page load, tab switch, scrolling, memory, CPU, battery, extension
install wall-clock, large pages, low-memory recovery. These require a device and Instruments.
One design risk is recorded from inspection: extension scripts are read from disk synchronously
inside `prepareContentScripts`, which runs on the main actor during navigation. With many
extensions on slow storage this can add latency; it is listed as a known issue (§8).

## 8. Known limitations and remaining risks

**Blocked by environment**

1. No device execution: browser, extension runtime, permissions UI and downloads are untested at
   runtime.
2. xtool build blocked by the missing Darwin SDK (`Xcode.xip`), so the primary build path is
   unverified; the CI lane is the only executed build.
3. No screenshots captured; `Scripts/capture-screenshots.sh` is provided but unrun.
4. App Store submission not attempted; guideline 4.7 review risk remains.

**Known product issues**

5. Unsynchronised main-actor file reads during content-script preparation (perf risk, §6).
6. CRX signatures are not verified; the UI says so.
7. Extension options pages are not hosted.
8. `webRequest`, cookies, alarms, i18n, DNR are unsupported; the analyzer states this.
9. Private browsing disables extensions (documented), which some users may not expect.

**Test gaps**

10. Cross-extension data access and token forgery are untested at runtime.
11. No fuzzing of the ZIP/CRX parsers (caps and rejection cases are unit-tested).
12. No low-memory or WebKit process-crash testing.
